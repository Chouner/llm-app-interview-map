# 数据格式

`data/graph.json` 是一个 JSON 对象：

```
version    版本号
title      图谱名称
sources    来源代码 → 说明，如 "iv": "真实面试追问"
modules    模块列表
nodes      知识点列表
```

## modules

| 字段 | 说明 |
| --- | --- |
| `id` | 模块 id，如 `eval` |
| `name` | 模块名称 |
| `groups` | 分组列表，每项 `{id, name, desc}`；可省略 |
| `links` | 和其他模块的关系说明，`{对方模块 id: 一句话}`；一对模块只需在其中一边写 |

## nodes

| 字段 | 说明 |
| --- | --- |
| `id` | 知识点 id，如 `ev-sample` |
| `m` | 所属模块 id |
| `g` | 所属分组 id；模块有分组时必填 |
| `name` | 名称 |
| `desc` | 通俗说明，1–2 句 |
| `role` | 在链路中的位置，1 句 |
| `points` | 面试里要能讲到的点，2–3 条 |
| `depth` | 三级深度：`[入门, 熟练, 深入]` |
| `pre` | 先修列表，每项 `[先修 id, 强度]`；强度 `h` 表示必须先会，`s` 表示先会更好 |
| `why` | 为什么需要每个先修，`{先修 id: 一句话}` |
| `src` | 来源代码列表 |

## 页面如何组织主线

每个知识点的“主线父节点”是同模块内的第一个 `h` 先修（没有就取同模块的第一个先修）。主线父节点在同一分组时，知识点挂在它下面；否则挂在自己的分组下。其他先修和后续显示在“和其他链路的关系”里。

## 校验规则

`scripts/validate.py` 检查：id 唯一、必填字段齐全、模块和分组存在、先修存在且无自环、整张图无环、`why` 只写先修、`depth` 正好三级。
